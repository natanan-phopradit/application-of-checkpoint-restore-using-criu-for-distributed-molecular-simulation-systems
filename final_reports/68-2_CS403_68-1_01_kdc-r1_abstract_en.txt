การประยุกต์ใช้ CHECKPOINT/RESTORE ด้วย CRIU สำหรับระบบการประมวลผลแบบจำลองโมเลกุลแบบกระจาย
Application of Checkpoint/Restore using CRIU for Distributed Molecular Simulation Systems
This project propose solution to mitigate processing progress loss in Volunteer Computing systems, which often faced uncertainty of volunteers that typical users will not have their computer turned on all the time, and failure of one’s system could happen at any time. The research propose a design for volunteer distributed computing system of molecular simulation, which utilizes checkpoint/restore function of CRIU in the environment to enable client’s capabilities of recovering and migrating processing states at hand to other peers via server to reduce impact to the whole project, promoting high availability and fault tolerance. The system consists of clients utilizing CRIU for Checkpoint/Restore operations, and a Middleware layer to govern operations and communicate with the servers. On the server side, a Coordination Server manages job queues via Apache Artemis, while Storage Servers - consisting of a Work Server for original tasks, a Snapshot Server for checkpointed states sent from clients, and a Result Server for final outputs - utilize MinIO for data storage. The fault tolerance mechanism is categorized into two types: Graceful Shutdown, which handle SIGINT/SIGTERM signals by performing a final checkpoint and immediately transfer the snapshot to the server for other clients to carry on; and Non-graceful Failure, handled by periodic checkpoints at regular intervals. These periodic checkpoints also serve as a heartbeat signal; if a client becomes unresponsive, the server re-enqueues the latest snapshot for another client to resume the work instantly. Performance testing using three model sizes (ligandCMET, benchMEM, and benchRIB) demonstrated that the system fully meets all functional requirements. While small and medium-sized models showed optimal performance in Checkpoint/Restore tasks, the large-scale model—containing over 2 million atom-revealed limitations in the time required for uploading large snapshot files, which might affect total runtime in system that face high uncertainties. In conclusion, while this technique effectively enhances fault tolerance for distributed computing, further optimization in snapshot management is necessary for massive-scale workloads to be viable in real-world production environments.

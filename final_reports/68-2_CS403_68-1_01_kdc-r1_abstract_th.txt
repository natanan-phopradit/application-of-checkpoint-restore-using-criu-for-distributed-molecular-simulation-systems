การประยุกต์ใช้ CHECKPOINT/RESTORE ด้วย CRIU สำหรับระบบการประมวลผลแบบจำลองโมเลกุลแบบกระจาย
Application of Checkpoint/Restore using CRIU for Distributed Molecular Simulation Systems
โครงงานนี้นำเสนอการออกแบบระบบการประมวลผลแบบจำลองโมเลกุลแบบกระจายในลักษณะ (Volunteer Computing) ซึ่งมักมีความไม่แน่นอนสูงจากการที่อาสาสมัครไม่สามารถเปิดคอมพิวเตอร์ได้ตลอดเวลาหรือระบบอาจเกิดการขัดข้องกะทันหัน ผู้วิจัยจึงได้เสนอการประยุกต์ใช้ Checkpoint/Restore ด้วย CRIU สำหรับระบบการประมวลผลแบบจำลองโมเลกุลแบบกระจาย เพื่อสร้างระบบต้นแบบที่สามารถบันทึก ย้ายสถานะ และกู้คืนการประมวลผลได้ ระบบประกอบด้วย Client ที่ใช้โปรแกรม GROMACS ในการประมวลผล CRIU สำหรับการ Checkpoint/Restore และ Middleware ในการควบคุมการทำงานและติดต่อสื่อสารกับ Server ในฝั่ง Server มี Coordination Server สำหรับจัดการคิวงานด้วย Apache Artemis และ Storage Servers ที่ประกอบไปด้วย Work Server สำหรับจัดเก็บงานต้นฉบับ, Snapshot Server สำหรับจัดเก็บ Snapshot และ Result Server สำหรับจัดเก็บผลลัพธ์ โดยใช้ MinIO ในการจัดเก็บข้อมูล กลไกการจัดการความล้มเหลวแบ่งเป็น 2 ลักษณะ คือ การจัดการความล้มเหลวที่จัดการได้ (Graceful Shutdown) ผ่านการดักจับสัญญาณ SIGINT/SIGTERM เพื่อทำ Final Checkpoint และส่งต่อสถานะไปยังเครื่องอื่นทันที และการจัดการความล้มเหลวที่จัดการไม่ได้ ผ่านระบบ Periodic Checkpoint ทุก 2 นาที ซึ่งทำหน้าที่เป็นสัญญาณ Heartbeat หาก Client เงียบหายไป Server จะนำ Snapshot ล่าสุดกลับเข้าสู่คิวงานเพื่อให้เครื่องอื่นรับช่วงต่อได้ทันที จากการทดสอบประสิทธิภาพด้วยแบบจำลอง 3 ขนาด (ligandCMET, benchMEM และ benchRIB) พบว่าระบบสามารถทำงานตามความต้องการของระบบได้อย่างครบถ้วน โดยแบบจำลองขนาดเล็กและกลางมีประสิทธิภาพดีเยี่ยมในการทำ Checkpoint/Restore แต่แบบจำลองขนาดใหญ่ที่มีจำนวนอะตอมกว่า 2 ล้านอะตอม พบข้อจำกัดด้านเวลาในการบีบอัดและอัปโหลดไฟล์ Snapshot ขนาดใหญ่ ซึ่งกินเวลาเกือบเท่ารอบการบันทึกอัตโนมัติ สรุปได้ว่าเทคนิคนี้สามารถช่วยเพิ่มความทนทานต่อความเสียหาย (Fault Tolerance) ให้กับระบบได้อย่างมีประสิทธิภาพ แต่สำหรับงานขนาดใหญ่มากควรมีการเพิ่มประสิทธิภาพการจัดการความคืบหน้าเพื่อให้คุ้มค่ากับการใช้งานในสภาพแวดล้อมจริง
